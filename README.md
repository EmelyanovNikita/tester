## Синтаксис: for, sleep, log и if

```
sdp_offer_1 = "v=0\r\n..."

for i in 1..100 {
    resp = ChannelAdd(SESSION_ID, 0, 0, true, sdp_offer_1, 0, "")
    sleep(0.5)
    resp = ChannelRemove(SESSION_ID, resp.channelId)
}
```

- `for i in a..b { ... }` — обе границы включительно; границы — целое число или переменная (`1..n`). Если `a > b`, тело не выполняется.
- Переменная цикла (`i`) доступна в теле как обычная переменная и после цикла хранит последнее значение.
- Циклы можно вкладывать друг в друга. `}` — на отдельной строке; `{` — в конце строки с `for` или на следующей (см. «Стиль скобок»).
- `sleep(секунды)` — пауза, секунды могут быть дробными (`sleep(0.5)`) или переменной (`sleep(delay)`).
- В логе и в сообщениях об ошибках команды внутри цикла нумеруются как `2.1`, `2.2`, где `2` — номер цикла.
- Пример: `scripts/many_steps/load_test_loop.txt` (то же, что `load_test_v2.txt`, но в 6 строк вместо 355).

### log

```
log("канал:", resp.channelId, "код:", resp.replyCode)
```

- Любое число аргументов через запятую; значения вычисляются как везде в сценарии (строка в кавычках, число, переменная, `resp.поле`, enum) и печатаются **одной строкой через пробел**: `[3] log: канал: 72057594037928107 код: RC_SUCCESS`.
- Запятая внутри кавычек аргументы не разделяет. Неизвестная переменная в аргументе — ошибка команды.

### if / else

```
if resp.replyCode == RC_SUCCESS {
    resp = ChannelRemove(SESSION_ID, resp.channelId)
} else {
    log("не удалось создать канал:", resp.replyCode)
}
```

- Условие — одно сравнение: `==`, `!=`, `<`, `>`, `<=`, `>=`. Операнды: число, строка в кавычках, переменная, `resp.поле`, enum.
- Если оба значения числа, сравнение числовое и точное (большие ID вроде `72057594037928107` не теряют точность, `2 < 10` верно). Иначе `==` и `!=` сравнивают строки, а `<`, `>`, `<=`, `>=` дают ошибку.
- Имя enum приводится к числу, поэтому `resp.replyCode == RC_SUCCESS` работает, хотя в JSON ответа `replyCode` — имя, а `RC_SUCCESS` — число 0. Строка в кавычках остаётся строкой.
- Ветка `else` необязательна. `if` и `for` вкладываются друг в друга.
- Команды внутри веток нумеруются так же, как в циклах: `3.1`, `3.2`.
- Важно: ответ с `reply_code` не `RC_SUCCESS` по умолчанию останавливает сценарий ещё до `if`. Чтобы проверять статус в сценарии, запускайте с `--continue-on-error`: ответ при этом всё равно сохраняется в переменную. Ошибки при этом по-прежнему считаются, и тестер завершится с кодом 1.
- Пример: `scripts/simple/channel_add_checked.txt`.

### Стиль скобок

Открывающую `{` можно писать в конце строки или одной на следующей строке; `else` — после `}` в той же строке или с новой строки. Стили можно смешивать:

```
if resp.replyCode == RC_SUCCESS
{
    ...
}
else
{
    ...
}
```

Между заголовком и `{`, а также между `}` и `else` допускаются пустые строки и комментарии. Закрывающая `}` всегда стоит на отдельной строке (или в виде `} else`).

## Подключение к MM

Тестер играет роль SSW: MM сам вызывает на нём `Connect` и сообщает session_id и адрес, после чего тестер подключается к MM и отправляет `CredentialsSend`. Вся эта логика находится в одном месте — пакете `internal/mmlink`:

- `connect.go` — сами шаги: `Dial` (подключение с повторами раз в секунду), `Authenticate` (`CredentialsSend`), `NewEstablisher` (собирает их вместе). Если логика подключения изменится, правится именно этот файл.
- `link.go` — `Link`: запоминает параметры первого `Connect` (повторные игнорируются) и даёт `Ensure()` — «подключиться, если ещё не подключены; иначе вернуть имеющееся соединение».
- `cmd/tester/server.go` — gRPC-сервер, на котором MM вызывает `Connect`; он только передаёт параметры в `Link`.

### connect() в сценарии

```
connect()
sleep(3)
resp = ChannelAdd(SESSION_ID, ...)
```

- `connect()` ждёт `Connect` от MM, подключается и аутентифицируется. Если соединение уже есть, команда пропускается (в логе `соединение уже установлено`), поэтому её можно ставить в начале каждого сценария или цикла.
- До `connect()` переменная `SESSION_ID` не определена, а вызов метода даёт ошибку «нет соединения с MM».
- Если в сценарии **нет** `connect()`, тестер подключается перед сценарием сам и ждёт `start_delay_sec` — как раньше. Если `connect()` есть, пауза после него — это обычный `sleep(...)` в сценарии, и `start_delay_sec` не применяется.
- В конфиге: `"start_delay_sec": 3` (секунды, можно дробные; `0` — без паузы; по умолчанию 3).
- Пример: `scripts/simple/channel_add_connect.txt`.

## Запуск

```
go build -o tester ./cmd/tester
./tester --path config/config.json -s scripts/simple/channel_add.txt
```

- по умолчанию сценарий останавливается на первой ошибке (в том числе на `reply_code`, отличном от `RC_SUCCESS`), тестер завершается с кодом 1;
- `--continue-on-error` — не останавливаться при ошибке, а дойти до конца и вернуть код 1, если ошибки были;
- `--keep-alive` — не завершать тестер после сценария.
