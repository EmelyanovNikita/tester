## Внутреннее устройство (логика работы)

### Хранение данных

Все переменные хранятся в **единой мапе** (словаре), где ключ — имя переменной, значение — строка. Это единое хранилище для всех типов данных.

**Как различаются типы:**
- **Простые значения** (числа, строки, булевы флаги) — хранятся как обычные строки. Число `5` хранится как `"5"`, строка `"hello"` — как `"hello"`.
- **Структурированные объекты** (ответы функций с несколькими полями) — хранятся как **JSON-строка**. Это позволяет сохранить все поля и вложенные объекты внутри одного значения.

Таким образом, в мапе лежат строки, но некоторые из них — это JSON-строки, а некоторые — обычные литералы.

---

### Чтение значения из переменной

Когда парсер встречает имя переменной (например, `a` или `resp`), он ищет его в мапе. Если переменная найдена, её значение (строка) возвращается.

**Особый случай — чтение поля объекта:**

Когда встречается конструкция `переменная.поле` (например, `resp.status`), логика меняется:
1. Из мапы достаётся значение переменной `resp` (это должна быть JSON-строка)
2. Эта JSON-строка **парсится** — превращается в структуру данных (объект с ключами и значениями)
3. Из этой структуры извлекается значение по ключу `"status"`
4. Полученное значение возвращается как строка

**Для вложенных полей** (`resp.codec.name`) процесс повторяется рекурсивно: сначала извлекается объект `codec`, затем из него — поле `name`.

**Важно:** при каждом обращении к полю JSON-строка парсится заново. Это упрощает код и гарантирует актуальность данных, но требует ресурсов.

---

### Запись значения в переменную

При присваивании `a = 5` или `b = "hello"`:
- Значение справа резолвится (вычисляется)
- Затем просто сохраняется в мапу под именем `a` или `b` как строка

**Особый случай — запись в поле объекта:**

При конструкции `переменная.поле = значение` (например, `resp.status = "RC_FAILED"`):
1. Из мапы достаётся JSON-строка переменной `resp`
2. Эта строка парсится в структуру данных (объект)
3. В этой структуре обновляется (или создаётся) ключ `"status"` с новым значением
4. Структура **сериализуется обратно в JSON** (собирается в строку)
5. Обновлённая JSON-строка сохраняется в мапе под именем `resp`

**Для вложенных полей** (`resp.codec.bitrate = 96000`) процесс аналогичен: сначала извлекается объект `codec`, внутри него обновляется поле `bitrate`, затем весь объект `resp` сериализуется обратно в JSON и сохраняется.

Таким образом, при каждом изменении любого поля **перезаписывается вся JSON-строка** целиком. Это гарантирует целостность данных, но требует сериализации всего объекта при каждом изменении. Для небольших объектов это приемлемо.
